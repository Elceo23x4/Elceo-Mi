# Expectation-Reality Delta Engine

The Expectation-Reality Delta Engine freezes ELCEO's pre-event market expectation before actual release data is available, binds the later release and market reactions back to that frozen expectation, and stores an immutable interpretation of whether reality confirmed, rejected, absorbed, delayed, reversed, remained ambiguous, or only qualified as a mispricing candidate. It is not cognition drift: cognition drift compares two cognition snapshots, while this engine compares a decision-time event expectation with the actual release, revision, price reaction, follow-through, related-market response, and post-event cognition shift.

An event expectation contains the expectation ID, release/event ID, event kind, scheduled release time, issued/data-cutoff timestamps, primary asset, affected assets and currencies, indicator kind/category, region/currency, importance, frozen forecast, frozen previous value, unit, expected economic meaning, expected policy pressure, expected asset direction, pre-event cognition snapshot ID, pre-event confidence and contradiction, expected confirmation conditions, and source/provenance references. It is created before actual or revised outcome data exists, and it contains no actual value, revised previous value, price reaction, follow-through, or outcome field.

Event reality copies the frozen forecast and previous value from the expectation, accepts the actual release and revised previous value only from the bound release ID, reuses `normalizeMacroSurprise()` for normalized surprise, reuses the existing price-reaction engine for primary and follow-through reactions, validates canonical related-market reactions, records post-event cognition loaded from persistence, and stores confidence, contradiction, and bias deltas without changing any confidence formula.

Release and reaction binding is strict. The release ID must match the frozen expectation's event/release ID. Primary and follow-through reactions must match the expected asset, event kind, release time, and frozen expected direction. Related-market reactions must be in the expectation's affected assets or an approved canonical causality map, must not be the primary asset, and must use the canonically derived direction. Caller-selected directions or unrelated markets cannot create confirmation.

The versioned price-path horizon policy is `expectation-reality-v1`: immediate uses one completed bar, confirmation uses three completed bars, and follow-through uses six completed bars. Window completion depends on completed bars, not wall-clock time, so weekends and market closures are gaps rather than zero-movement candles. Delayed confirmation is reachable only when confirmation is absent in the three-bar confirmation horizon and appears during bars four through six.

Observation sets carry asset, timeframe, source/provenance, observed window, canonical content hash, observation version, and completed candles. The engine calculates the canonical content hash internally from ordered observation content and rejects supplied hash mismatches. It rejects asset/timeframe mismatches, invalid timestamps, opened-at-or-after-closed-at candles, candles opened before the expectation or release cutoff unless verified as post-event splits, non-positive OHLC values, invalid OHLC relationships, wrong bar duration, duplicate/out-of-order candles, future candles, and reuse of the same observation version with different content.

Path reality is volatility-normalised with the pre-issuance `recentRangePct`. Material movement is 0.50 volatility units, confirmation movement is 1.00 volatility unit, and strong movement is 1.50 volatility units. Missing or zero volatility context returns `insufficient_data` with `volatility_context_unavailable`; outcome candles are never used to estimate volatility.

Path-order logic records whether confirmation, contradiction, explicit invalidation, or same-candle order ambiguity happened first. Bullish expectations treat upward movement as favourable and downward movement as adverse; bearish expectations invert that logic. Neutral expectations are confirmed only when terminal movement stays below material magnitude and neither side reaches confirmation magnitude. Large two-sided neutral excursions are not clean confirmations. Mixed or unsupported expectations are not scored as failures, though realised path metrics remain preserved.

Invalidation is read from the frozen cognition invalidation state. The engine does not infer invalidation from arbitrary drawdown. If confirmation and invalidation occur in the same candle without finer-grained proof, the result records intrabar order unknown rather than fabricating sequence.

Event interpretation combines release-alignment delta, primary price reaction, follow-through, canonical related-market response, revision effect, confidence/contradiction shift, provenance, and volatility limitations. A material surprise alone is not confirmation. `mispriced_candidate` is strictly qualified: it requires material normalized surprise, reliable release provenance, semantic alignment or explicit semantic contradiction, primary rejection or absorption, later verified follow-through, directionally consistent related-market confirmation, and no critical missing volatility, provenance, or timing evidence. It is always a candidate, never proven mispricing.

Persistence is append-only: expectations are unique by expectation ID and source cognition/release identity; path evaluations are unique by expectation, horizon, and observation version; event evaluations are unique by expectation and release version. The same observation version is content-bound by hash across horizons, and idempotent replay returns the identical immutable record while conflicting immutable writes fail. SQL stores event/release IDs, release versions, primary event outcomes, pre/post cognition snapshot references, observation hashes, timezone-aware timestamps, and JSON audit payloads.

Limitations: the engine measures expectation-reality divergence and event interpretation evidence. It does not output buy, sell, or hold instructions, does not alter confidence formulas, and does not treat missing related-market evidence as fabricated confirmation.

Later IFP phases can consume these immutable deltas as evidence for Historical Market Memory, Contradiction-to-Action, Market Cleanliness, News Half-Life, Crowd Pain, and Fragility Score without changing the frozen expectation or its original audit trail.
