## Family summary

- Auth/framework routes are `no_product_entitlement_required`; framework auth is not product-entitlement gated.
- Dashboard keeps kick-off basic slices while premium cognition/deep slices require focus plan/subscription checks.
- Journal basic surfaces remain kick-off allowed; journal influence/deep generation requires focus plan.
- Workspace, portfolio, analytics, coaching, refresh, dashboard, journal, and notification summary carry commercial restriction-first expectations.
- Account/profile/social identifiers are authenticated owner-only; external LinkedIn/Telegram/X ownership verification remains outside RC-E.
- Admin/internal routes require internal-token evidence; commercial user mutations require target-user, step-up, idempotency, and audit/security evidence.
- Billing/payment routes are readiness/blocker paths; live checkout/session activation remains blocked.

## Routes marked blocked_live_activation

- `/api/billing/checkout`
- `/api/internal/market-evidence/tiingo/fixture-ingest`

These remain blocked/readiness/dry-run only; RC-E does not activate live KoraPay/Stripe checkout/session creation, notification live sends, or provider-live ingestion.

## Explicitly not present

Public SEO API routes and journal deep-analysis routes beyond the live route filesystem are `not_present`; RC-E does not create them.

## Remaining risks

Production deployed-auth smoke, real provider webhook provenance, and live payment/notification provider activation require environment verification and credentials; they are intentionally not faked in local CI.
